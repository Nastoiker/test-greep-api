# Чат MAX

Тестовое задание: отправка и получение текстовых сообщений через GREEN-API.
React, TypeScript, MUI, TanStack Query, Vite. Серверная часть не нужна.

Онлайн-версия: https://max-green-api-chat.vercel.app

Для входа нужны данные своего инстанса GREEN-API.

## Запуск

Нужен Node.js 22.12 или новее.

```sh
git clone https://github.com/Nastoiker/test-greep-api.git
cd test-greep-api
npm ci
cp .env.example .env
npm run dev
```

Открыть http://127.0.0.1:5173.
В PowerShell вместо `cp` можно использовать `Copy-Item .env.example .env`.
Если PowerShell блокирует `npm.ps1`, запускайте команды через `npm.cmd`.

## Разработка в Docker

Нужен запущенный Docker Desktop с Linux-контейнерами (на Windows — WSL 2).

```sh
docker compose up -d --build
docker compose logs -f web
```

Открыть http://127.0.0.1:5174. Порт можно изменить через `DOCKER_PORT` в `.env`.
Порт 5173 остаётся свободным для обычного запуска через npm.

Рабочая папка подключена к контейнеру. Сохраняйте TSX, TS и CSS в редакторе — Vite обновит страницу через hot reload. Для Windows включён polling. Linux-зависимости хранятся в отдельном volume и не смешиваются с локальным `node_modules`. `.env` читается из рабочей папки, в образ он не копируется.

После изменения зависимостей выполните `docker compose restart web`: при старте запускается `npm ci`. Пересобирать образ после правок исходников не нужно.

```sh
docker compose ps              # состояние контейнера
docker compose exec web npm run check
docker compose down            # остановить
```

Контейнер настроен для разработки, не для публичного размещения. Для автозапуска после входа в Windows включите запуск Docker Desktop: сервис использует `restart: unless-stopped`.

## Подключение GREEN-API

1. Создайте инстанс MAX в [GREEN-API](https://console.green-api.com/) и авторизуйте аккаунт.
2. В настройках включите `incomingWebhook: "yes"`, а `webhookUrl` оставьте пустым.
3. Для статусов доставки включите `outgoingWebhook: "yes"`.
4. Введите `idInstance`, `apiTokenInstance` и `apiUrl` в форме входа. Адрес сервера возьмите из своего инстанса.
5. Создайте чат по номеру, отправьте сообщение и ответьте на него с телефона получателя.

Поддерживаются номера РФ и Беларуси. Получатель должен разрешать поиск по номеру в MAX.
Enter отправляет сообщение, Shift + Enter добавляет строку. Максимум — 4000 символов.

## Настройки

В `.env.example` указаны адрес API, таймауты и интервалы повторных запросов. Скопируйте файл в `.env` и при необходимости измените значения. После изменения перезапустите dev-сервер.

| Переменная                     | По умолчанию                     |
| ------------------------------ | -------------------------------- |
| `VITE_GREEN_API_URL`           | `https://3100.api.green-api.com` |
| `VITE_REQUEST_TIMEOUT_MS`      | `40000`                          |
| `VITE_RECEIVE_TIMEOUT_SECONDS` | `25`                             |
| `VITE_POLL_INTERVAL_MS`        | `350`                            |
| `VITE_RETRY_INITIAL_MS`        | `1000`                           |
| `VITE_RETRY_MAX_MS`            | `30000`                          |

Настройки проверяются при запуске и сборке. Таймаут запроса должен быть больше времени ожидания уведомления.
Не добавляйте токен в `VITE_*`: эти значения попадают в клиентскую сборку. Токен вводится в форме и хранится в памяти страницы.

## Структура

Проект разделён по FSD:

- `app` — точка входа, QueryProvider, тема MUI и стили;
- `pages` — экраны входа и чата, состояние переписки;
- `features` — авторизация, создание чата, ввод сообщения;
- `entities` — типы и операции с чатами, тип сессии;
- `shared` — HTTP-клиент, схемы Zod, настройки и общие компоненты.

Внешние импорты идут через `index.ts`, внутри среза — относительные пути. Правила импортов проверяются тестом.

React Query управляет запросами. Черновики и сообщения хранятся в reducer страницы, поэтому переключение чата не сбрасывает ввод. Входящие уведомления обрабатываются последовательно: получение, обработка, подтверждение. Повторные уведомления отсекаются по ID сообщения.

Отправка не повторяется автоматически: если HTTP-ответ потерялся, сообщение уже могло уйти. При выходе запросы отменяются, кэш очищается.

## Проверки

```sh
npm run check
npx playwright install chromium
npm run test:e2e
```

Первая команда проверяет ESLint, форматирование, тесты, типы и сборку. Вторая устанавливает браузер для Playwright.
Браузерные тесты используют подменённые ответы GREEN-API. Реальную доставку нужно проверять со своим инстансом.
Скриншоты тестов сохраняются в `docs/screenshots/`.

Отступы — два пробела. `npm run lint:fix` исправляет замечания ESLint, `npm run format` форматирует проект.
Для форматирования при сохранении в VS Code нужны расширения ESLint и Prettier.
Проверки для GitHub Actions находятся в `.github/workflows/check.yml`.

## Ограничения

- После обновления страницы вход и переписка сбрасываются. Загрузка истории не реализована.
- Обработанные уведомления удаляются из очереди API и повторно не загружаются.
- Используйте одну вкладку на инстанс: несколько вкладок или другой бот будут забирать сообщения из общей очереди.
- Поддерживаются только текстовые сообщения.

## Сборка

```sh
npm run build
npm run preview
```

Готовые файлы находятся в `dist/`. Их можно разместить на статическом HTTPS-хостинге.

### Публикация на Vercel

Сборка настроена в `vercel.json`. После входа в свой аккаунт:

```sh
npx vercel login
npx vercel deploy --prod --project max-green-api-chat
```

Текущая версия опубликована через CLI. Автоматическая публикация при push в GitHub не настроена.
Локальные `.env` исключены из загрузки через `.vercelignore`; используются значения по умолчанию из `shared/config`.

Документация GREEN-API: [отправка](https://green-api.com/v3/docs/api/sending/SendMessage/), [получение уведомлений](https://green-api.com/v3/docs/api/receiving/technology-http-api/), [поиск по номеру](https://green-api.com/v3/docs/api/service/CheckAccount/).
